# Active Suspension 方案 v1.0

## 1. 文档目的

本文档描述 `active_suspension` 模块在复杂地形下的一条可落地演进路线。

这里的目标不是：

- 永远强行让四个悬挂末端处于同一个平面
- 永远强行让底盘绝对水平

这里的目标是：

1. 优先保证机器人安全。
2. 尽可能维持稳定支撑。
3. 在可行范围内尽量减小底盘 `roll/pitch`。
4. 始终尊重悬挂行程、执行器限制和姿态变化平顺性。

本方案基于当前已有的几何工具和悬挂正逆解模块：

- `active_suspension_geometry.hpp`
- `ground_inverse_calculation.cpp`
- `pose_forward_kinematics.cpp`

并在其基础上补足复杂地形下真正需要的策略层和安全层。

## 2. 当前模块的角色

当前 `active_suspension` 文件夹里已经有 3 个很有价值的基础块。

### 2.1 几何基础层

`active_suspension_geometry.hpp` 负责定义：

- 向量、平面、局部几何结构
- 坐标变换
- 旋转工具
- 悬挂上端安装点 `A1~A4` 的统一几何约定

它是整个模块的数学基础。

### 2.2 Ground Inverse

`ground_inverse_calculation.cpp` 当前主要做下面这些事：

1. 构建上端锚点 `A1~A4` 的几何关系。
2. 读取当前悬挂角 `theta_1~theta_4`。
3. 重建四个悬挂下端点 `B1~B4`。
4. 由 `B1~B4` 拟合支撑平面。
5. 输出平面系数和坡度信息。

它本质上是一个“当前支撑面几何观测器”。

### 2.3 Pose Forward Kinematics

`pose_forward_kinematics.cpp` 当前主要做下面这些事：

1. 接收一个目标平面。
2. 把底盘上端锚点平面当作车体参考平面。
3. 反解四个悬挂角 `theta_1~theta_4`。

它本质上是一个“目标支撑几何 -> 关节目标角”的几何反解器。

## 3. 为什么当前逻辑还不够

当前逻辑在“地面可以近似成单一平面”的情况下是合适的。

但在下面这些情况里就不够用了：

- 台阶
- 棱边
- 石块
- 四角高度明显不同
- 局部悬空
- 支撑面快速切换

根本原因是：复杂地形下，很多时候根本不存在一个同时适合四个支撑点的单一平面。

因此，后续的控制策略必须停止默认以下前提：

- 四个下端点永远共面
- 四个接触点永远同等可信
- 最优控制目标永远是“绝对水平”

## 4. 总体架构

建议的控制链路如下：

`传感器输入 -> 几何重建 -> 接触估计 -> 支撑几何估计 -> 模式选择 -> 车体目标姿态规划 -> 约束求解 -> 安全过滤 -> 执行器执行 -> 反馈修正`

这是一套分层架构。

每一层只负责一件明确的事。

## 5. 详细流程

## 5.1 第一步：采集传感器输入

第一步是收集主动悬挂所需的所有原始状态。

建议输入包括：

- IMU `yaw`
- IMU `pitch`
- IMU `roll`
- IMU `pitch_rate`
- IMU `roll_rate`
- 四个悬挂关节角
- 四个悬挂关节角速度
- 四个电机电流或力矩估计（如果有）
- 底盘速度（如果有）
- 触地传感器（如果有）
- 地形感知传感器（如果有）

这一层还需要做：

- 时间戳对齐
- 有限值检查
- 信号滤波
- 毛刺剔除
- 每路信号有效性标记

这一层输出：

- 同步后的状态向量
- 各输入的有效标记

这一层不负责做控制决策，只负责给后续模块准备可靠输入。

## 5.2 第二步：重建悬挂几何状态

这一步要根据车体姿态和关节状态，重建当前悬挂在空间中的真实几何关系。

核心工作：

1. 构建上端锚点 `A1~A4`。
2. 使用几何参数 `l`、`L` 等。
3. 使用每条腿当前关节角 `theta_i`。
4. 重建下端点 `B1~B4`。

几何含义上：

- `A_i` 表示车体侧悬挂锚点
- `B_i` 表示地面侧或支撑侧悬挂末端

这一层回答的是：

- 当前每个悬挂末端到底在空间哪里
- 当前支撑几何到底长什么样

这一层正是当前 `ground_inverse_calculation.cpp` 的强项，应该保留并继续利用。

这一层输出：

- 世界坐标系下的 `A1~A4`
- 世界坐标系下的 `B1~B4`
- 每条腿的径向方向
- 每条腿的几何状态

## 5.3 第三步：接触状态估计

这是未来设计里最关键的新增层之一。

系统不能再默认四个角永远都在可靠承重。

对于每个悬挂角，都应该估计它当前属于哪一类：

- 可靠接触
- 轻载接触
- 滑移接触
- 不确定接触
- 悬空
- 卡滞或异常受阻

这个估计不能只看几何，最好结合多个信号一起判断：

- 关节角变化
- 关节角速度
- 电机电流或力矩估计
- 末端点的重建运动
- IMU 响应是否一致
- 与支撑模型之间的残差

例如：

- 电流很大但角度几乎不动，可能表示强接触或卡住。
- 角度在明显变化但电流很小，可能表示轻载甚至悬空。
- 接触存在但接触点持续相对滑动，可能表示低附着、局部打滑或支撑参考不稳定。
- 某个角相对拟合平面的残差特别大，可能表示压在局部石块上，或者它根本不该被放进同一平面模型里。

这一层输出：

- 每个角的接触状态
- 每个角的接触可信度

这一步很重要，因为后面所有决策都依赖“哪些接触可信”。

## 5.4 第四步：估计当前支撑几何

这里不再强制要求把四个 `B_i` 永远拟合到同一个平面上，而是做鲁棒的支撑几何估计。

典型情况包括：

### 情况 A：四点近似共面支撑

条件：

- 四个接触都比较可靠
- 四点拟合平面残差较小

处理：

- 使用四点拟合一个支撑平面

这对应普通坡地或者轻微起伏地形。

### 情况 B：三点支撑 + 一点异常

条件：

- 三个接触点可靠
- 另一个点残差大或者接触可信度低

处理：

- 使用三个可靠点定义支撑平面
- 第四点只作为柔顺跟随或次要约束

这对应的场景例如：

- 某一个轮子压过石块
- 某一个角跨过局部凸起
- 某个角暂时轻载

### 情况 C：四点接触但非共面

条件：

- 四个角的接触可信度都较高
- 四个角都表现出明显承载
- 但四点拟合单一平面的残差较大
- 不能合理地用一个普通平面描述四个支撑点

处理：

- 不再把四点共面作为硬约束
- 保留四个角各自的接触高度、残差和载荷信息
- 用“虚拟支撑面”只作为姿态参考，而不是作为严格几何真值
- 后续求解改为软约束优化，而不是单平面精确反解

这对应的场景例如：

- 一只脚压在石块上，另外三只脚仍正常承载
- 前后分别处于不同高度的平台
- 左右分别压在不同斜面上
- 地面、接触垫或结构本身存在柔顺变形

### 情况 D：边缘或近似线支撑

条件：

- 只有两个点高度可靠
- 正在跨越台阶边缘或明显不连续地形

处理：

- 不再积极追求调平
- 优先保证稳定与平顺

### 情况 E：支撑几何不稳定或不可解释

条件：

- 接触关系快速变化
- 当前时刻无法可信地建立支撑模型

处理：

- 进入保护性行为
- 降低控制激进程度

### 情况 F：单点或无有效支撑

条件：

- 只有一个点可靠接触
- 或者所有接触都不可靠
- 或者机器人处于短时腾空、跌落、剧烈脱离支撑的状态

处理：

- 不再尝试估计稳定支撑平面或支撑线
- 直接进入保护控制
- 优先限制姿态变化、关节动作和冲击
- 待重新建立可信接触后再恢复正常模式

这一层输出：

- 当前支撑类型
- 当前支撑几何
- 当前支撑质量评分
- 若有意义则输出支撑坡度估计

## 5.5 第五步：模式切换

根据支撑几何估计结果，系统应该进入不同的控制模式。

至少建议有以下 4 种模式。

### 模式 1：平面调平模式

适用条件：

- 当前支撑可以很好地近似为一个平面
- 接触可信度高

行为：

- 主动减小底盘 `roll/pitch`
- 允许使用更积极的调平增益

### 模式 2：三点支撑模式

适用条件：

- 某一个角不可靠或轻载
- 三个点可以清晰定义支撑关系

行为：

- 以可靠的支撑三角形来定义车体姿态参考
- 第四个角柔顺跟随

### 模式 3：扭曲四点支撑模式

适用条件：

- 四个角都在接触并承载
- 但四点不能被一个单平面合理描述

行为：

- 不再强制四点共面
- 以“尽量平、尽量稳、尽量不超限”为目标
- 使用软约束分配四角悬挂量
- 优先减小载荷不均和局部过约束

### 模式 4：边缘跨越模式

适用条件：

- 支撑关系变化很快
- 正在跨越台阶、棱边或明显不连续地形

行为：

- 优先平顺过渡
- 降低调平增益
- 避免突然拉动单个角

### 模式 5：保护模式

适用条件：

- 行程接近极限
- 支撑解释不稳定
- 单点或无有效支撑
- 出现明显冲击或异常电流
- 传感器或执行器反馈异常
- 目标几何不可达

行为：

- 降低速度
- 降低命令带宽
- 限制车体修正量
- 必要时降低车体或冻结部分命令

这一层输出：

- 当前控制模式
- 当前模式下的控制增益和约束

必须有这层状态机，因为不同地形场景本质上是不同控制问题，而不只是同一个算法里换几个参数。

## 5.6 第六步：生成车体目标姿态

这一层决定的是：

“下一时刻，我希望车体朝什么姿态去变。”

目标不应该永远固定为：

- `roll = 0`
- `pitch = 0`

更合理的做法是根据模式和可行性来生成目标。

典型目标如下：

### 在平面调平模式下

目标：

- 尽量逼近水平姿态
- 但保持在允许的姿态范围内

### 在三点支撑模式下

目标：

- 在支撑三角形上尽量稳定
- 尽量减小过大倾角
- 但不强迫系统实现不可能的几何关系

### 在边缘跨越模式下

目标：

- 保证姿态连续
- 减小突变
- 保证支撑稳定

### 在保护模式下

目标：

- 优先安全
- 避免撞限位
- 降低动态风险

这一层输出：

- 目标车体 `roll`
- 目标车体 `pitch`
- 若需要则输出目标车体高度
- 若需要则输出每个角的附加偏置

这一层负责把“理想控制意图”转化成“可执行的姿态目标”。

## 5.7 第七步：做带约束的求解或小规模优化

这是整套方案里最核心的决策层。

这里的任务是：

- 在当前机械约束和支撑约束下
- 找到最合适、最安全、最可实现的悬挂命令

建议的优化变量包括：

- 车体 `roll`
- 车体 `pitch`
- 车体高度（如果需要）
- 四个悬挂角 `theta_1~theta_4`

典型目标项包括：

- 减小车体倾角
- 减小悬挂偏离中位量
- 减少不必要的大动作
- 若有载荷估计，则减小四角载荷不均
- 减小相对当前稳定状态的偏离

典型约束包括：

- 关节角上下限
- 关节速度限制
- 关节加速度限制
- 几何可达性
- 最小离地间隙
- 支撑稳定性约束
- 当前模式下的接触规则

这里最重要的原则是：

- 如果系统无法在不违反约束的情况下实现完全水平，就应该选择“最优的安全妥协解”，而不是强行输出一个理论上漂亮、实际上不可执行的命令。

这一层输出：

- 可行的目标悬挂状态
- 可行的目标车体姿态

它比纯单平面反解更强，因为它明确地区分了“想要什么”和“实际上能做到什么”。

## 5.8 第八步：把目标姿态转换成关节目标角

一旦目标支撑几何或者目标车体姿态已经确定，就需要转换成四个实际的悬挂关节目标角。

这里正是 `pose_forward_kinematics.cpp` 继续有价值的地方。

当前角色：

- 输入一个目标平面
- 解出目标 `theta_1~theta_4`

未来更合理的角色：

- 从更丰富的目标输入中反解 `theta_1~theta_4`
- 输入可以扩展为：目标车体姿态、当前支撑模式、局部地形约束等

这一层输出：

- 四个悬挂角的目标值

这一层应该尽量保持“几何、确定、可解释”的特性。

## 5.9 第九步：安全过滤与轨迹整形

即使前一层已经算出了合法目标角，也不能直接把这些值生硬地下发给执行器。

中间必须有一层安全过滤和轨迹整形。

建议至少包含：

- 角度限幅
- 速度限幅
- 加速度限幅
- jerk 抑制
- 突变抑制
- 模式切换平滑

这一层确保：

- 命令在物理上可跟踪
- 执行器冲击更小
- 接触关系切换时不容易振荡

这一层输出：

- 平滑、安全、可执行的关节轨迹

## 5.10 第十步：执行器执行

这一层是底层伺服执行层。

职责包括：

- 跟踪关节目标角
- 遵守电机与硬件限制
- 回传可靠反馈

这一层可以运行在 1000 Hz，甚至更高。

但必须明确一点：

- 高频率只能提高对合理命令的跟踪能力
- 不能纠正错误的地形模型假设

这一层输出：

- 实际关节运动结果
- 更新后的电机与关节反馈

## 5.11 第十一步：反馈验证与在线修正

每执行完一个控制周期，系统都应该验证：

- 车体 `roll` 是否按预期减小
- 车体 `pitch` 是否按预期减小
- 是否有某个角突然轻载或悬空
- 是否有某条腿接近行程极限
- 当前支撑几何是否发生突变
- 当前控制模式是否仍然有效

如果答案是否定的，就要及时回退并修正，例如：

- 切换模式
- 降低控制激进程度
- 重新规划目标姿态
- 回退到更安全的行为

这一层把整套系统闭合成一个在线自适应控制回路，而不是一次性几何求解。

## 6. 主要设计原则

后续实现建议始终遵守以下原则。

### 6.1 不强制四点共面

复杂地形下，强行要求四个支撑点共面往往在物理上就是错的。

更合理的做法是：

- 鲁棒拟合平面
- 三点支撑逻辑
- 异常点剔除

### 6.2 不把高频率等同于鲁棒性

1000 Hz 对低层跟踪有用，但如果模型本身错了，再高频也不会自动变对。

正确的模型层次和控制分工，比单纯提高频率更重要。

### 6.3 几何层和策略层分离

几何层应该回答：

- 当前支撑几何是什么
- 什么关节值能实现某个目标几何

策略层应该回答：

- 当前支撑模型是否可信
- 当前应该追求什么姿态目标

这两类职责不应该混在一起。

### 6.4 安全优先于完美调平

当完全调平不可实现时：

- 不要强迫输出
- 应优先选择稳定、安全、部分补偿的方案

## 7. 推荐的软件模块拆分

建议后续软件结构至少拆成下面这些部分。

### 7.1 传感器状态聚合器

职责：

- 收集和同步 IMU、关节、电流等输入
- 检查输入有效性

### 7.2 悬挂几何重建器

职责：

- 计算 `A_i` 和 `B_i`
- 保留并扩展当前 `ground_inverse` 的能力

### 7.3 接触估计器

职责：

- 为每个角给出接触状态和可信度

### 7.4 支撑分析器

职责：

- 拟合支撑平面或支撑三角形
- 检测异常点和不稳定支撑

### 7.5 悬挂模式管理器

职责：

- 在不同控制模式之间切换
- 管理每种模式的增益和约束

### 7.6 车体姿态规划器

职责：

- 生成目标 `roll`、`pitch` 和高度

### 7.7 可行性求解器

职责：

- 求解满足约束的目标悬挂状态

### 7.8 关节命令生成器

职责：

- 把目标姿态或目标支撑几何转换成关节目标角

### 7.9 安全过滤器

职责：

- 限速
- 饱和处理
- 模式切换平滑

## 8. 建议的实现路线

建议按阶段逐步推进。

### 阶段 1：保留并增强现有几何层的可观测性

任务：

- 保留当前几何工具
- 保留当前 `ground_inverse`
- 保留当前 `pose_forward_kinematics`
- 增加 `A_i`、`B_i`、平面残差、求解有效性等调试输出

目标：

- 让当前几何层可视化、可调试、可验证

### 阶段 2：增加接触可信度估计

任务：

- 估计每个角的接触可信度
- 发布每个角的状态标记
- 识别异常角和共面失配情况

目标：

- 不再把四个角都视为等价且完全可信

### 阶段 3：增加支撑类型分类

任务：

- 分类四点平面支撑
- 分类三点支撑
- 分类边缘过渡支撑
- 分类无效或保护性状态

目标：

- 为模式切换建立真正可靠的依据

### 阶段 4：加入模式管理器

任务：

- 实现状态机
- 定义进入和退出条件
- 定义各模式的控制增益和约束

目标：

- 避免所有地形场景都硬套一套控制逻辑

### 阶段 5：加入车体目标姿态规划器

任务：

- 按模式生成目标 `roll`、`pitch`、高度
- 保证姿态目标有界且连续

目标：

- 把车体姿态目标和低层反解逻辑彻底分开

### 阶段 6：加入带约束的求解层

任务：

- 求“最优可行解”，而不是只求“理论完全调平”
- 把行程限制、速度限制等纳入求解

目标：

- 从理想几何迈向真实硬件可实现控制

### 阶段 7：集成安全过滤层

任务：

- 加入轨迹整形
- 加入模式切换平滑
- 加入异常命令抑制

目标：

- 让控制器能在真机上平顺执行，而不是只有数学上成立

## 9. 预期收益

相比当前单平面假设，这套方案预计会提升：

- 台阶和棱边场景下的鲁棒性
- 部分接触情况下的行为稳定性
- 对不可实现命令的保护能力
- 控制行为的可解释性
- 支撑切换过程中的安全性

## 10. 总结

未来的主动悬挂控制不应该只是：

`观测一个平面 -> 反解一个平面 -> 输出关节命令`

更合理的完整方案应该是：

`观测几何 -> 估计接触 -> 识别支撑形态 -> 选择控制模式 -> 规划可行车体姿态 -> 求解安全悬挂命令 -> 平滑执行 -> 在线验证并修正`

当前代码库已经具备不错的几何基础块。

真正还缺少的是几何观测、反解求解和真实执行器控制之间的那一层“决策与约束管理层”。

这层补上之后，`active_suspension` 才能从“数学解算模块”真正演进成“复杂地形可用的主动悬挂控制系统”。
